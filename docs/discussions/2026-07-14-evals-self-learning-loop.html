0Thesis

Luna already has a real supervised feedback loop. What it does not have is a closed self-improvement loop with a measurement instrument. That second loop is designed (Dream v2) and mostly unbuilt past Phase 1.

Product bet (keep it). Improve local state and artifacts - beliefs, memory, skills, workflows - under operator ground truth. Do not fine-tune weights on personal traffic. That is closer to good personal-agent architecture than most "self-learning" marketing.

1Three layers that look like evals

Only Layer 1 is a closed product loop today. Layer 2 is engineering instrumentation. Layer 3 is the designed self-improvement system.

Alignment loop

Nightly Dream → proposed beliefs / memory hygiene → survey (task_quality + belief_validation) → activate/retire → inject beliefs into system prompt. Global EWMA only controls survey cadence.

Trust model (load-bearing)

Two signals, never one scalar

  • Global alignment EWMA - "how often should I survey?" Attention budget only.
  • Per-belief confidence + history - gates actions in that domain only.
  • A week of great coding help must not unlock autonomous finance outreach.
  • Cold start: dormant, surveys daily, climb by earning validated beliefs.
Measure-only firewall

Logged, cannot steer yet

  • Calibration / ECE - verbalized dream confidence vs outcomes.
  • Sample agreement - SelfCheckGPT-style multi-pass; pass 1 materializes.
  • Tier classifier - 0/1/2 from confidence × stakes × reversibility.
  • Intentional: collect honesty data before auto-gated self-modification.

4Dream v2 - the target self-improvement loop

Open proposal space. Closed gate taxonomy. Human answers mint ground truth. Nothing ungated auto-applies. Scorers live in substrate and are structurally unwritable by dream workers.

Behavioral

Golden set + judge

Black-box end to end. Works for any lever. Pinned judge, different family than generator. κ ≥ 0.6 or inconclusive.

Retrieval

Recall / ranking

Query→memory pairs, live vs shadow. For embedding / index / retrieval config changes.

Integrity

Schema + probes

Row counts, referential checks, harness-corpus binary floor. Structural safety.

Cost / latency

Telemetry deltas

Surfaced as trade-offs, not silent wins. Quality without a blank check.

6State of the art (2025–2026)

Agent eval moved from static Q&A benches to long-horizon, tool-using, environment-grounded harnesses. Self-learning usually means artifact + context updates under gates - not personal RLHF.

Border colors map roughly to Luna readiness: green = solid today, amber = partial, red = designed/missing. SOTA expects the full flywheel.

Swiss cheese

Never one eval layer

Offline suite + production monitoring + human review + failure→dataset flywheel. Single layers leak; combined layers catch.

What to score

Outcome + trajectory

Environment state (booking made, test green), tool selection/order/schema, action advancement vs completion, instruction adherence, cost.

Self-learning types

Three different things

Weights (RLHF/DPO/RLVR) - labs. Artifacts (DSPy/GEPA/skills) - production agents. User model (memory/beliefs) - personal agents. Luna targets 2+3, supervised.

Philosophy is strong for a local single-operator agent. Measurement instrument and gated promote path are the holes.

Trenchant observation. The risk is not "we forgot RLHF." The risk is running Dream proposals without a measurement instrument, so "self-improvement" becomes unfalsifiable opinion. The product question is: what are we allowed to change, and what instrument proves the change was good? Design already answered it. Implementation has not.

8Recommendation

Narrowed: ignore the full Dream v2 phase ladder for now. Ship one lane — Dream proposes skill improvements as chips. Full gates/goldens stay design, not the next PR.

Do next

Phases 2 → 3 → 5

  • Chips so proposals are visible
  • Trajectory recorder for replay later
  • Golden set as the measurement instrument
  • Shadow sandbox experiment MVP (chips only)
  • Productize TrainingHarness as golden-case runner
Cheap parallel wins

Wire implicit labels

  • Permission denials → task_quality pre-bias
  • Keep LoCoMo / recall as retrieval regression
  • Keep harness-corpus as integrity floor
  • Leave calibration measure-only until ECE/κ look honest
Explicitly defer

Until scoreboard exists

  • GEPA-class structural rewrites
  • Tier 0 auto-apply
  • Cross-instance packs
  • Any weight training path
  • Vendor-centric eval SaaS as source of truth
